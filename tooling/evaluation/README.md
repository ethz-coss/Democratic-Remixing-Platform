# Evaluation Module

Post-simulation analysis tools that extract data from PocketBase (or from
saved JSON result files), compute quantitative metrics, generate plots, and
package everything into self-contained experiment bundles.

Works identically on data generated by simulated agents and by real human
participants — no special flags or modes are needed.

---

## 📊 Experiment Data Export (`evaluation/extract/export.py`)

The `evaluation/extract/export.py` script is a comprehensive data extraction tool designed for researchers and analysts. It securely connects to the PocketBase API and packages all platform data grouped by **experiment** (which maps to the `groups` collection). It automatically pseudonymizes user identifiers (e.g. by hashing IDs and wiping PII fields) to ensure privacy.

### What it Exports
For each group/experiment, the script creates a dedicated folder named `exports/YYYY-MM-DD_<GroupName>_<GroupID>/` inside the directory you ran it from. It populates this folder with the following CSV files, perfectly filtered for that specific experiment:

- `groups.csv`: The group's metadata and settings.
- `group_members.csv`: The mapping of users to this group (user IDs pseudonymized).
- `users.csv`: User demographics and profile data (filtered strictly to group members; names, avatars, and usernames wiped; emails randomized; IDs pseudonymized).
- `study_consents.csv`: Ethics agreements and consent records for the group members (user IDs pseudonymized).
- `questions.csv`: The questions/discussions associated with this group.
- `question_phases.csv` & `question_timeline_events.csv`: The progression and lifecycle events of the questions.
- `proposals.csv`: All ideas and solutions submitted within the questions (author IDs pseudonymized).
- `question_votes.csv` & `proposal_votes.csv`: All voting data (user IDs pseudonymized).
- `contradiction_edges.csv`: The contradiction graphs and severing votes.
- `action_logs.csv`: Detailed telemetry and interaction logs (user IDs pseudonymized).
- `labels.csv`: Proposal labels.
- `ballot_responses.csv`: Final ranking ballots (user IDs pseudonymized).
- `proposal_hides.csv`: Hidden proposals (user IDs pseudonymized).
- `user_proposal_views.csv`: Proposal viewing telemetry (user IDs pseudonymized).

> **Note**: All CSVs automatically adapt to the schema. Any future fields added to these collections in PocketBase will automatically be included in the export without needing to modify the script.

### Running Locally against Production
Because the script uses standard HTTP requests, you can run it directly from your local machine to securely download data from your live production server.

**Mac/Linux:**
```bash
PB_URL="https://your-production-domain.com" \
PB_ADMIN_EMAIL="admin@your-domain.com" \
PB_ADMIN_PASSWORD="your-secure-password" \
python3 evaluation/extract/export.py
```

**Windows (Command Prompt):**
```cmd
set PB_URL=https://your-production-domain.com
set PB_ADMIN_EMAIL=admin@your-domain.com
set PB_ADMIN_PASSWORD=your-secure-password
python evaluation\extract\export.py
```

### Running Locally against Local Dev Environment
If you are testing locally and the SvelteKit / PocketBase containers are running, you can run it without environment variables, as it defaults to the local PocketBase URL and credentials:
```bash
python3 evaluation/extract/export.py
```
*(Default URL: `http://127.0.0.1:8090`, Default Admin: `admin@admin.com`, Default Password: `1234567890`)*

## Quick Start

```bash
# From the simulations/ directory:

# Generate plots for all experiments (live PocketBase, recommended):
python -m evaluation.run_evaluation --batch-experiments

# Single experiment by question ID:
python -m evaluation.run_evaluation --question-id <PROBLEM_ID>

# Offline mode (from JSON result files, no PocketBase needed):
python -m evaluation.run_evaluation --batch --offline

# With metrics computation and experiment bundle:
python -m evaluation.run_evaluation --batch --offline --compute-metrics --bundle

# Compare two experiment bundles:
python -m evaluation.run_evaluation \
  --compare output/experiments/exp_a_*/ output/experiments/exp_b_*/
```

Plots are saved to `output/plots/<label>/run_<timestamp>/` by default.

## CLI Reference

```
python -m evaluation.run_evaluation [OPTIONS]
```

### Input Flags

| Flag | Default | Description |
|------|---------|-------------|
| `--batch-experiments` | off | Generate plots for all experiments from live PocketBase |
| `--question-id` | — | PocketBase question record ID to analyse (online mode) |
| `--json-result` | — | Path to a simulation result JSON (e.g. `output/run_1.json`) |
| `--batch` | off | Generate plots for all `output/run_*.json` or `output/exp_*.json` files |
| `--offline` | off | Reconstruct data from JSON only — no PocketBase needed |

### Connection Flags

| Flag | Default | Description |
|------|---------|-------------|
| `--base-url` | auto-discovered | PocketBase URL (online mode) |
| `--admin-email` | `$PB_SUPERUSER_EMAIL` | Admin/superuser email (online mode) |
| `--admin-password` | `$PB_SUPERUSER_PASSWORD` | Admin/superuser password (online mode) |
| `--output-dir` | `output/plots/` | Directory to save output plots |

### Analysis Flags

| Flag | Default | Description |
|------|---------|-------------|
| `--compute-metrics` | off | Compute all evaluation metrics and save as `metrics.json` |
| `--bundle` | off | Create a self-contained experiment bundle (config + data + metrics + plots) |
| `--compare DIRS...` | — | Compare two or more experiment bundle directories |
| `--compare-output` | `output/comparison.md` | Output path for comparison report |

### Mode Summary

| Mode | Flags | PB Required? | Description |
|------|-------|-------------|-------------|
| All experiments | `--batch-experiments` | Yes | Fetch from live PocketBase |
| Online single | `--question-id <ID>` | Yes | Single question from PB |
| Online from JSON | `--json-result <path>` | Yes | Reads `question_id` from JSON, fetches from PB |
| Offline single | `--json-result <path> --offline` | No | Reconstruct from JSON only |
| Offline batch | `--batch --offline` | No | All JSON files in output/ |
| Online batch | `--batch` | Yes | JSON files, fetch from PB |
| Compare bundles | `--compare <dir1> <dir2>` | No | Compare saved bundles |

## Evaluation Pipeline

The full evaluation pipeline follows this sequence:

```
Input (PocketBase or JSON)
  │
  ├─ 1. Data Extraction
  │     pb_extractor.py (online) or json_extractor.py (offline)
  │     → QuestionData: solutions, votes, action_logs, clusters, champions, focus
  │
  ├─ 2. Standard Plots
  │     plot_timeline.py → Support timeline or snapshot bar chart
  │     plot_merges.py   → Merge progression, acceptance, triggers
  │
  ├─ 3. Metrics Computation (--compute-metrics)
  │     metrics.py → MetricsReport (participation, graph, merges, convergence)
  │
  ├─ 4. Extra Plots (--compute-metrics)
  │     plot_metrics.py → Heatmap, DAG, convergence curve, distribution, composition
  │
  └─ 5. Bundle Packaging (--bundle)
        bundle.py → Self-contained directory with all outputs
```

## Metrics Reference

When `--compute-metrics` is enabled, the following metrics are computed:

### Participation Metrics

| Metric | Description |
|--------|-------------|
| `total_actors` | Number of unique users who performed any action |
| `total_solutions` | Total solution count |
| `total_votes` | Total positive votes cast |
| `content_creation_rate` | Fraction of actors who authored at least one solution |
| `voting_engagement` | Average votes per actor |
| `actions_per_agent_mean` | Mean actions per active user |
| `actions_per_agent_median` | Median actions per active user |
| `actions_per_agent_std` | Standard deviation of actions per user |
| `actions_per_agent_max` | Maximum actions by any single user |
| `phase_activity_distribution` | Action count split into early/mid/late thirds |

### Graph Metrics

| Metric | Description |
|--------|-------------|
| `node_count` | Number of solutions in the DAG |
| `edge_count` | Number of parent→child edges |
| `density` | Graph density (edges / possible edges) |
| `connected_components` | Number of connected components (undirected) |
| `giant_component_fraction` | Fraction of solutions in the largest component |
| `max_depth` | Deepest remix chain in the DAG |
| `mean_depth` | Average depth across all solutions |
| `median_depth` | Median depth across all solutions |
| `branching_factor` | Average out-degree of non-leaf nodes |
| `cluster_count` | Number of distinct clusters (schools of thought) |
| `convergence_ratio` | Fraction of edges that are merge edges |

### Merge Dynamics Metrics

| Metric | Description |
|--------|-------------|
| `total_merge_solutions` | Number of solutions with 2+ parents |
| `merge_fraction` | Merge solutions / total solutions |
| `status_counts` | Breakdown by merge_status (none/pending/partial/accepted) |
| `acceptance_rate` | Accepted merges / total merge solutions |
| `partial_rate` | Partial merges / total merge solutions |
| `vote_migration_count` | Number of vote migration events |
| `siphon_ratio` | Support on child solutions / total support |

### Convergence Metrics

| Metric | Description |
|--------|-------------|
| `support_gini` | Gini coefficient of support distribution (0=equal, 1=concentrated) |
| `effective_solution_count` | Inverse Simpson index (1/HHI) — how many solutions effectively share the support |
| `champion_dominance_ratio` | Top champion support / 2nd place champion support |
| `solutions_with_support` | Number of solutions with at least 1 vote |
| `total_support` | Sum of all support counts |
| `focus_concentration` | Fraction of total support held by focus solutions |
| `champion_count` | Total number of cluster champions |

## Plots Generated

### Standard Plots (always generated)

#### Support Timeline (`support_timeline.png`)
Auto-selects between two rendering modes:
- **Timeline mode** (votes have timestamps): Step-function time-series of cumulative support per solution, colored by cluster.
  - ◆ markers = idea emergence, ★ markers = champion transitions
  - Thick lines with glow = focus solutions
  - ▲/▽ markers = merge status (accepted/partial/pending)
- **Snapshot mode** (no timestamps): Horizontal bar chart grouped by cluster.

#### Merge Analysis (`merge_progression.png`, `merge_acceptance.png`, `merge_triggers.png`)
Three views of merge dynamics: status progression over time, acceptance rates, and what triggered each merge.

#### Combined View (`likes_and_merges_combined.png`)
Overlays support timeline with merge event annotations.

### Extra Plots (with `--compute-metrics`)

#### Participation Heatmap (`participation_heatmap.png`)
Agent × time-bucket activity grid. Color intensity shows number of actions per agent per time window. Agents sorted by total activity, limited to top 40 for readability.

#### Remix DAG Graph (`remix_graph.png`)
Solution graph visualized with networkx. Nodes colored by cluster, sized by support. Champion nodes have gold borders. Remix edges are solid, merge edges are dashed orange.

#### Convergence Curve (`convergence_curve.png`)
Dual-axis time-series: Gini coefficient (left axis, pink) and effective solution count (right axis, blue). Shows whether and when the platform converges.

#### Vote Distribution (`vote_distribution.png`)
Horizontal bar chart of solutions ranked by support count. Top 30 solutions shown, colored by cluster. Champions marked with ★.

#### Action Composition (`action_composition.png`)
Stacked bar chart showing the mix of action types (vote, create, merge, comment, other) over time buckets. Reveals the evolving nature of platform activity.

#### Metrics Comparison Table (`comparison_table.png`)
Side-by-side table comparing key metrics across experiments. Generated via `--compare`.

## Experiment Bundles

A bundle is a self-contained directory packaging everything needed to reproduce and analyze one experiment:

```
exp_05_day30_b_20260605_155622/
├── config.yaml              # Experiment configuration (agents, seed, LLM settings)
├── report.json              # Raw simulation report (full decision/event log)
├── metrics.json             # Computed evaluation metrics
├── summary.md               # Human-readable experiment summary
├── extracted/
│   ├── solutions.csv        # All solutions with metadata
│   ├── votes.csv            # All votes with timestamps
│   ├── action_logs.csv      # All action log entries
│   └── graph_edges.csv      # Parent→child edges for the DAG
└── plots/
    ├── support_timeline.png
    ├── merge_progression.png
    ├── merge_acceptance.png
    ├── merge_triggers.png
    ├── likes_and_merges_combined.png
    ├── participation_heatmap.png
    ├── remix_graph.png
    ├── convergence_curve.png
    ├── vote_distribution.png
    └── action_composition.png
```

### Creating Bundles

```bash
# Manual bundle creation:
python -m evaluation.run_evaluation --json-result output/exp.json --offline --compute-metrics --bundle

# Auto-bundle during experiment run:
python run_experiments.py --compute-metrics --bundle
```

### Comparing Bundles

```bash
# Compare two experiment runs:
python -m evaluation.run_evaluation \
  --compare output/experiments/exp_a_*/ output/experiments/exp_b_*/

# With custom output path:
python -m evaluation.run_evaluation \
  --compare output/experiments/exp_a_*/ output/experiments/exp_b_*/ \
  --compare-output my_comparison.md
```

The comparison generates a markdown report with:
- Configuration differences between experiments
- Side-by-side metrics table with all numeric metrics

## YAML Experiment Configs

Experiments can be defined as YAML files for reproducibility:

```yaml
experiment:
  name: "30-day convergence with 100 agents"
  description: "Full convergence test over 30 simulated days with merge dynamics"
  run_id: "exp_05_day30"
  label: "Exp 5 - Day 30"

  simulation:
    agents: 100
    seed: 42
    target_duration_days: 30
    max_steps: 200
    merge_probability: 0.15
    migration_move_probability: 0.8
    branch_pressure: 0.5

  llm:
    provider: "github-models"
    model: "openai/gpt-4.1-mini"
    temperature: 0.7
    enabled: true       # Set to false for dry runs (cost saving)
    token_budget: 0     # 0 = unlimited

  pocketbase:
    base_url: "http://localhost:18090"
```

Load configs via:
```bash
python run_experiments.py --config-dir configs/
```

### Key Classes

| Class | Module | Purpose |
|-------|--------|---------|
| `QuestionData` | `pb_extractor` | Container for all extracted data: solutions, votes, action_logs |
| `SolutionRecord` | `pb_extractor` | Single solution with metadata, parentage, cluster info |

| Function | Module | Description |
|----------|--------|-------------|

| `plot_remix_graph(...)` | `plot_metrics` | Solution DAG visualization |

## Common Workflows

### 1. Quick Offline Evaluation (No PocketBase)

```bash
python -m evaluation.run_evaluation \
  --json-result output/exp_05_day30_b.json \
  --offline \
  --compute-metrics \
  --bundle
```

### 2. Full E2E Pipeline (Simulate + Evaluate)

```bash
# Option A: Shell script
./run_e2e_pipeline.sh

# Option B: With cost-saving dry run (no LLM)
./run_e2e_pipeline.sh --disable-llm

# Option C: Manual two-step
python run_experiments.py --disable-llm --compute-metrics --bundle
python -m evaluation.run_evaluation --batch --offline --compute-metrics --bundle
```

### 3. Cross-Experiment Comparison

```bash
# Run two experiments with different seeds
python run_experiments.py --seed 42 --bundle --compute-metrics
python run_experiments.py --seed 99 --no-clean --bundle --compute-metrics

# Compare them
python -m evaluation.run_evaluation \
  --compare output/experiments/exp_*_42_*/ output/experiments/exp_*_99_*/
```

### 4. Human Trial Evaluation

The same pipeline works for human-generated data. After a real session:

```bash
# Extract from live PocketBase with metrics and bundle
python -m evaluation.run_evaluation \
  --question-id <REAL_PROBLEM_ID> \
  --compute-metrics \
  --bundle

# Compare human vs simulation
python -m evaluation.run_evaluation \
  --compare output/experiments/human_trial_*/ output/experiments/sim_baseline_*/
```
